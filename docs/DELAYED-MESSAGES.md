# 延时发送固定文字

主代理、子代理输入框右侧的“延时”按钮打开当前会话的计划面板。
填写分钟数（1–10080，即最多七天）和固定文字，点击“安排发送”。
各会话分别保存计划，不会投递到旁边的会话。

到点后，主会话使用唤醒输入；可继续子代理通过宿主原生继续入口恢复，
保留原子代理 ID、父子关系和宿主保存的执行配置。一次性子代理不支持后续
对话，投递会显示失败，不会创建替代代理。

DSH 须运行才能执行。关闭 DSH 或电脑期间不会发送；下次 DSH 启动后，
未到期计划恢复计时，已到期计划补发，无需先打开原会话。
如果直接父代理本身是尚未恢复的子代理，计划显示“等待重试”，等待原父代理
可用后再尝试。普通根父会话可以通过正式宿主恢复入口加载。

面板打开时在查询完成两秒后再次刷新，显示待发送、发送中、等待重试、核对回执、
已送达和失败。错误原因直接显示在对应计划下。“已送达”表示宿主确认了
该条消息的持久接收，不代表模型已成功回答，也不会重置供应商额度。

尚未开始投递的计划可以取消；发送中或回执未知的计划不能保证撤回。
不确定宿主是否接受时，只核对原消息，不以新 ID 再发。取消原生会话中的
未消费消息后，原计划也不会自动再造一条消息。

0.4.2 修正此前使用 `inject` 的错误：它既不能恢复已释放的子代理，
也不会主动唤醒空闲主代理。还修正延时重试被回合模板处理、发送中状态在
重启后卡住，以及会话范围计时器要先打开原会话才恢复的问题。

旧版尚未尝试发送的计划可以继续执行。旧版曾尝试发送却缺少固定消息标识
的计划会显示失败说明，需先核对会话记录再决定是否重新安排，避免重复。

与“冻结”不同：冻结等待后继续原请求的同一步；延时会新增一条固定文字。
两者都不会重放已经完成的工具操作，也不能唤醒已关机的电脑。
