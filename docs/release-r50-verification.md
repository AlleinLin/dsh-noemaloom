# R50 / 0.4.2 延时发送修复验收

目标宿主为官方 DeepSeek Harness Desktop 0.2.1-rc.5。R50 修复主代理和子代理
“延时”固定文字没有真正进入下一回合的问题；本次没有更新宿主或同源 SDK。
用法见 [延时发送说明](DELAYED-MESSAGES.md)。

旧实现只调用 `inject`，无法唤醒空闲主会话或恢复已释放的原生子代理。
新实现分别使用主会话唤醒输入和官方子代理继续入口，保留原子代理 ID、
直接父会话及执行配置。计划拥有固定请求标识，核实宿主日志和持久化回执后
才显示“已送达”；不确定时仅核对原消息，避免重复发送。重启会恢复有活动
计划的原范围，无需先打开原会话。错误、等待原因和投递状态显示在计划面板。
冷主会话通过官方 `sessionController.resolveAgent` 恢复模型选择和预设；
界面查询串行刷新，慢于两秒的回复也能显示。

本轮验证：

- 本地全套回归 2479 项通过，0 失败、取消、跳过；最终 22 项相关回归通过，
  包含两秒以上慢回复的真实浏览器 DOM 验证。
- TypeScript 检查、构建、生成物检查、交付包审计通过，npm 审计为 0 漏洞。
- 使用独立官方 rc.5 桌面、全新合成 profile 和本地模型适配器，实际完成六项
  验收：原生可继续子代理释放；主输入栏定时文字进入模型请求；已释放的
  子代理收到文字且保留原父子关系；取消不发送；关闭并重启隔离桌面后原
  主、子会话计划均实际进入模型请求；相同请求标识重复查询不新增原生消息。
- 验收未读取或复制真实用户 profile，未调用远程供应商；隔离桌面已关闭。
