# 桌面端性能与辅助请求生命周期

## 范围

此优化在 Nexus 插件的客户端执行，覆盖原生会话里的独立辅助、自动计划、
子代理分析、图谱桥接、命令输出监视器和轻量编辑器调试面板。
不通过停止代理、清空上下文、删除数据或降低模型上下文覆盖来换性能。
既有摘要缓存、模型上下文前缀和有界编辑器/图谱缓存继续使用。

浏览器和 DSH 会竞争系统 CPU、内存、GPU 和磁盘；插件可以减少自己给宿主增加的
负担，但不能隔离操作系统资源，也不能保证解决工作机所有卡顿。
本机的进程内存快照不能替代工作机的长期剖析。

## 本次发现与处理

- 辅助面板原先在 `running` 变化时中止生命周期，却合并复用旧读取；
  旧 AbortError 可能写入新生命周期，随后成功读取仍保留旧错误。
  现在运行状态只要求刷新，生命周期只随会话、连接代际或卸载结束；
  合并限于同一信号，成功读取清除旧错误。重连主动重新读取，动作不因运行状态切换中止。
- 若任务取消或插件重启后只留下持久的“检查中”，读取会核对实际在途检查；
  没有存活检查才恢复为 `AUXILIARY_INTERRUPTED` 并开放手动重试。
  存活检查保持原状，恢复状态本身不调用模型，避免永久禁用重试和永久快速轮询。
- 原生会话注入入口只订阅必要的身份/运行字段；流式 token 不再驱动辅助面板和计划入口重渲染。
  编队分析使用独立的 200ms 展示采样，不改变原生会话数据源或输入。
- 所有迁移到 `visiblePoll` 的只读监视器单次读取完成后才安排下一次；
  重复刷新最多合并为一次后续读取，失败指数退避，上限 120 秒，成功后恢复正常间隔。
  页面隐藏时移除计时器，重新可见时读取最新状态，不补跑历史轮询。
- 独立辅助有检查/前置问题时约 2 秒读取，普通运行时 8 秒、空闲时 30 秒；
  停用或未配置时 120 秒。已忽略提示的反馈倒计时在 20 秒后停止，
  前置问题的倒计时也在到期后停止，不留下永久每秒渲染。
- 折叠且未执行的自动计划 30 秒读取，展开或计划推进时 8 秒。
- 图谱的原生目录同步和流式回复按 100ms 合并，只拼接最新文本；
  没有更新时无计时器，隐藏时暂停桥接，恢复后发送最新状态。
  Synapse 原页面自己的每秒投影轮询也接入经过来源校验的父面板显隐消息；
  面板收起但 iframe 的 `document.hidden` 仍为假时，也不会继续轮询。
  卸载释放原生会话引用、订阅、观察器和待处理计时器。
- 命令输出在活跃时 700ms、追赶分页时 40ms、空闲时 8 秒读取；
  调试面板活跃时 350ms，空闲时 10 秒。隐藏时暂停读取，实际命令和调试进程照常运行。
  重复快照不触发无意义状态更新，一页调试输出合并为一次更新。
- 连接重置和插件释放有明确的本地取消原因；RPC 擦除原因时也保留归属。
  没收到本地取消信号的远端 AbortError 单独报告，不宣称用户停止；
  辅助模型仍按已设置的优先级退避，正式操作不自动重放。

## 验证与限制

回归使用实际 React 组件与隔离 Chromium，检查运行状态切换、明确重试、
连接重建、远端中止和成功恢复。另有可控时钟检查慢请求、隐藏窗口一小时、
1000 次刷新合并、流式突发以及 500 次创建/释放。
这些是调度与生命周期的确定性验证，并非工作机的整体 FPS 或内存改善百分比。

如果工作机仍越用越卡，采样时请区分：

1. DSH 静置、窗口隐藏、重新显示，以及多会话流式输出时的 CPU/专用内存变化。
2. 打开/关闭图谱、子代理栏、命令监视器、编辑器前后的变化。
3. 浏览器退出后是否立刻恢复，系统可用内存是否接近耗尽。
4. 是否出现辅助失败码、连接重建；导出当时的最新会话日志。

不要将 `NX_OBSERVATION_DEFERRED` 独立记账等待恢复解释为主模型请求已被取消；
也不要用历史 session 导出判断另一个时间发生的中断。
