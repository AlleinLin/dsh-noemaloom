# R34 请求与上下文恢复

R34 默认对失败模型请求进行最多 64 次退避重试，主、子代理一致。
原请求不计入重试次数；可在全局、工作区、会话设置调整次数和算法。

- PI_AI_ERROR、UNKNOWN、无明确取消来源的适配器中断、网络、网关、
  HTTP 拒绝与内部请求错误均进入同一策略。
- 用户、主会话或明确钩子取消立即停止，等待中也可取消。
- 以真实取消信号和生命周期事件为准，服务端仅返回取消或释放错误码
  不会冒充用户取消，也会按同一预算重试。
- 原生提供方白名单及旧 PI 开关不再导致第 0 次停止。
- 默认 0.5 秒起步、2 倍指数退避、30 秒封顶、10% 随机抖动；
  服务端 Retry-After 优先，长等待可取消且不会触发 Node 定时器溢出。
- 流在正式结束前抛错会进入原生恢复入口；
  完整成功响应之后的 PI 收尾错误保留成功结果，避免重复执行工具。
- 超限先退避重试压缩恢复，只有正式压缩提交且占用缩减后才重发。
  压缩忙或失败不再受独立的 2 次上限限制。
- 压缩已替换但最终收据暂时失败时，下一次恢复核对原收据，
  沿用已证明缩减的结果，不额外生成摘要或再次替换。
- 自动维护失败只重试维护阶段，不重放一次性的请求中间件链。
- 重试设置读取失败使用已知策略或默认值，并单独记录读取故障。
- 重试计数写入原生会话事件，插件重新加载后仍受同一预算约束。

重试保持原轮次、原步骤，不补造“继续”消息。权限、预算和正式收据
继续校验；不会越权请求、重放已完成工具或重复未知效果的正式操作。
会话删除、代理释放、插件卸载及无法写入正式会话事件会明确终止恢复。
错误耗尽时保留原代码、阶段、追踪 ID、次数和停止原因。

回归覆盖实际 DSH 原生驱动的主代理及子代理：连续 64 次 PI 失败后恢复、
第 65 次失败耗尽、等待中取消、流异常、原步骤保持及工具仅执行一次。
同时覆盖设置继承、策略重载、上下文恢复阶段和维护准入中间件不被跳过。
测试使用本地可控提供方，不向用户账户发送故意失败的模型请求。

安装仍使用同一插件和安装脚本；从托盘退出 DSH 后安装，不修改会话、
工作区、数据库和用户模型配置。此版本不承诺修复上游服务本身。
