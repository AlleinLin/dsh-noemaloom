# 步骤进度

本能力适配自 [cxv117793-blip/dsh-step-pause 0.3.0](https://github.com/cxv117793-blip/dsh-step-pause/tree/eeb93a7ff027e4beba94b8089dfb72dfe45b2550)，许可证为 MIT。完整许可、未修改的上游宿主源码与包清单、提交与 SHA-256 记录保留在 `notices/step-pause/`，并列入 `sources.lock.json`。目标宿主为 DSH `0.2.1-rc.2`；没有引入第二个插件运行时或模型服务。

在 DSH 设置 → Nexus 设置 → **步骤进度** 中选择全局、工作区或会话，保存设置。未填写的字段随父级实时继承；选择“恢复继承”只清除当前范围的覆盖。修改从下一个步骤边界生效，已经进入模型的提示不会从历史删除。

如果另外安装了原版 `dsh-step-pause`，请停用其中一个，避免同一步收到两次进度提示。此适配不接管原版配置。

| 设置 | 默认值 | 行为 |
| --- | --- | --- |
| 启用步骤进度 | 开启 | 关闭后原任务正常运行 |
| 每多少步汇报一次 | 10 | 1–500；第1步不汇报，设为1从第2步开始 |
| 每轮最多汇报几次 | 0 | 0不限，最多可配置1000 |
| 只在主智能体汇报 | 开启 | 排除宿主真实子智能体；手动 fork 仍可作为独立主会话 |
| 显示提示词原文 | 关闭 | 开启后可见原文；其生产者元数据仍标记为插件提示 |
| 进度提示词 | 当前任务、已完成、下一步、卡点 | 支持 `{{step}}`、`{{every}}`、`{{turn}}` |

“分步暂停”是上游名称，含义是暂时切换到进度汇报，然后立即继续。它在 `agent/pre-step` waterfall 中只调用一次 `next()`，等待宿主审批与其它监听器给出允许进入的决策，再在**本步骤消息末尾**追加提示。它不会中断正在执行的工具，不会等待用户确认，不会建立新回合，也不会私自重放模型请求或工具。原生请求恢复仍由 DSH 负责，同一已准入步骤中的提示只提交一次；任务结束后不发送新的继续消息。

该提示是 `role: user` 的普通模型输入，会按宿主原有机制持久化、参与上下文与压缩。隐藏原文只是显示设置，不消除 token 成本；模型输出进度也消耗输出 token。默认提示要求原任务权限、审批、取消和输出格式优先，禁止中间文字或严格机器格式的任务继续保持原格式。模型是否实际汇报仍取决于其响应，并非强制保证。

宿主接线位于 `src/host/step-pause-hook.ts`，沿用 Nexus 的消息生产者标识，状态绑定精确 Agent 对象、Session 对象与原生 `(turn, step)`。配置读取失败、超时或身份不确定时记录诊断并跳过此次提示，原始已准入决策继续执行；取消、拒绝、卸载或 Agent 替换后不追加。上游读不到归属时仍向主智能体注入的宽松回退在此处收紧为跳过。主会话、子会话与并行工作区之间不共享计数或发送状态。显示原文的提示也不会被意图识别、自主规划、旁路审阅、记忆检索与提取或恢复记录当成新的人类需求。

设置复用 `scope/settings`、`scope/configure`、`scope/reset`，功能键为 `step-pause`。持久化格式为：

```json
{
  "enabled": true,
  "defaults": {
    "everyNSteps": 10,
    "maxReportsPerTurn": 0,
    "mainAgentOnly": true,
    "showPromptInChat": false
  }
}
```

仅当前连接的用户设置界面可以修改此功能策略；模型工具、子智能体和远程观察者不能改变它。每步仅追加固定模板渲染后的尾部提示，不修改 system 前缀、原始任务或历史消息；UUID 仅为宿主消息身份，不进入提示文本。

开发回归文件为 `tests/step-progress.test.ts`、`tests/step-progress-consumers.test.ts` 与 `tests/native-step-progress.test.ts`。消费者回归通过实际会话桥与记忆 hook 检查提示来源分类。原生回归使用已安装的正式 Cordis、AgentRegistry、AgentLoop、SessionStore、ToolRuntime 和本地假模型适配器，覆盖步骤触发、长工具、正式同一步重试、一次性提交、并行根会话、真实子会话、读取失败与卸载。它不调用真实模型，不能证明某个供应商一定遵守进度文案。完整验证统一运行 `npm run check` 和 `npm run pack:delivery`；桌面入口需在独立测试 profile 中确认。
