## 原因

来源选择和 summarize 早期检查原来只统计原始来源 JSON。
发送前，host-adapter 又将这个 JSON 包装进原生消息，
附加系统提示词、消息结构，并重新序列化检查。
原始来源能放下不代表完整请求能放下；大量引号和反斜杠会进一步扩大差距。

这条路径的前后检查不一致，导致选中的来源到了最终发送检查才被拒绝。
旧用例在摘要 hook 处用替身返回结果，未穿过真实 host-adapter 的最终检查。

## 修复与回归

范围选择按完整摘要请求预算二分，保留完整工具配对与未选尾部。
host-adapter 与选择器共用原生输入消息构造器和序列化预算函数。
宿主最终检查保留，不能通过放松检查发送越界请求。

回归覆盖包含大量转义字符的多消息来源、无可容纳完整前缀、
UTF-8 与严格预算边界。成功用例穿过 production summarize、
host-adapter、真实上下文准备模块和官方 LlmRuntime，
在本地模型适配器收到的实际请求上独立检查最终序列化大小。
无需真实模型或工作机即可验证请求构造和正式事务边界；
