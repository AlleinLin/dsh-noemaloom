# 侧栏布局交互修复（R24）

## 触发方式

在原生右侧栏点击四宫格“分栏与布局”，尚未选择菜单项，菜单没有显示，侧栏失去点击和滚动；收起再展开仍不恢复，刷新后可恢复。

## 修改范围

宿主 `SidebarPanel` 使用 `pointer-events: none`，原生 `TabHost` 在内容边界恢复 `pointer-events: auto`。插件用 `DockSurface` 与自己的内容树替换原布局时，没有保留这条内容边界，导致标签栏、菜单和正文继续继承外层的不可交互状态。隔离 Desktop 中已观察到旧版按钮实际命中外层容器，而不是按钮自身。

插件自己的 `.nexus-native-dock-tree` 恢复与原生 `TabHost` 等价的指针事件边界。它只影响该插件渲染的原生内容树。

原布局入口还使用标签栏内部的原生 `details`。菜单依赖该标签栏的裁剪与定位，也没有按侧栏隐藏或会话切换关闭菜单的生命周期。

布局入口改为浏览器非模态 `popover`。菜单进入 top layer，按按钮位置定位；只有插件自己的触发按钮和菜单声明可接收指针事件，不修改宿主或其他插件的全局输入状态。外部点击、Escape、侧栏隐藏、会话切换、窗口尺寸变化和组件卸载均有关闭流程。原分栏和布局业务操作保留。

上述代码问题与现场现象相符；现场未采集到运行时命中区域或调用栈，隔离 Desktop 的对照结果与工作机复核结果分别记录。

## 验证

修改和验证脚本完成后统一运行构建、类型检查、自动回归及产物检查。桌面交互对照使用全新临时配置，不复制用户会话或凭据，不发送模型请求。

交互验证包括菜单动作的实际命中、侧栏点击和滚轮、外部点击与 Escape，以及侧栏收起后重新展开。组件回归另覆盖会话身份变化和卸载。报告必须区分前置条件失败、菜单关闭失败和整个侧栏失去交互，不以菜单 DOM 存在代替可操作性。

结果以本轮验收记录和实际测试回执为准。使用真实工作机会话重新验证：点击四宫格后菜单应显示，菜单内操作及侧栏原有点击和滚动应可用，关闭再打开侧栏后也应可用。

本轮 Windows Desktop 临时配置验收通过：10 项实际检查覆盖窗口就绪、正式会话归属、侧栏点击及滚轮、菜单命中与外部关闭、Escape、收起重开、菜单防裁剪和隐藏／会话身份变化／卸载清理。另一个仅用于旧版被阻挡入口的键盘诊断分支在新版跳过，不计入这 10 项。最后一次验收使用宿主正常显示的窗口，没有模拟焦点；首次配置选择“稍后配置”，未填入账号或密钥。

旧版对照确认了缺失的输入边界；未完整重现工作机“先可操作、点四宫格后才失效”的初始状态转移。工作机仍应按上面的触发步骤复核。
