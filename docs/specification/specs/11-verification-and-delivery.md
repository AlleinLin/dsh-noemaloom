# 11 验证、迁移、实施计划与交付门槛

本章区分**规格已完成**与**插件已实现并通过验收**。本次交付只做静态研究、文档校验与UI概念稿验证；未执行上游项目、未运行其单元测试、未调用收费模型基准，也未安装新插件。下面所有运行性指标都是实施期必须验证的目标，不冒充已经得到的结果。加入Metis后的完整开发顺序以第13章及机器任务DAG为准，本章阶段表为归组概览，不能用其早期阶段范围漏掉新多模型能力或Claude桌面外观。

## 3. 缓存与论文压缩联合实验

第07章是本节的详细协议。本节定义总体放行条件。

### 3.1 必须有的实验臂

1. 锁定上游 `billion-context/acp-kernel`，在可比Host接法下的未改造基线。
2. Nexus复用相同内核并整合Host、固定工具目录和记忆的基线。
3. 加入Nexus缓存计划器、精确锚点、epoch与增量报告的候选。
4. 关闭压缩的有限窗口对照，仅在可完成的相同任务长度内比较，不拿无法完成的运行宣称更便宜。

相同任务、模型身份、Provider、采样参数、工具结果、初始上下文、并发与时间价格条件要尽量配对。远端cache有共享/预热污染风险，实验顺序随机或交叉，记录冷/暖、时间间隔和请求身份。不可把作者生产论文结果当本机对照结果。

### 3.2 任务集合

至少包括：500+轮合成增量开发、真实风格代码迭代、跨文件重构、长故障排查、重复读取减少、压缩后精确值恢复、约束续接、多代理协作、分支/回退、改persona/工具epoch、Provider切换、stream中断/重试、多个账户与网关、缓存自然过期。

每个任务有预先固定的完成判据和准确性探针，例如早期需求中的端口/路径/版本号、被否决方案、当前未完成工作、代码编译/行为、工具配对、源引用。仅测“能回答摘要问题”不够证明长程开发接手质量。

### 3.3 必报指标

- `reported_cache_hit_tokens / reported_prompt_tokens`，按token加权；只对有对应上报的请求计算，并报覆盖率。
- 未命中token、压缩输入/输出、正常输出、重试、外部API、辅助模型和已取消已计费请求。
- 供应商真实费用或按版本化价格表估算；峰谷/节假日/单位/币种/管理与推理费区分。
- TTFT、总延迟、P50/P95；压缩事件前后warming曲线。
- 输入总量、压缩比、层级写放大、工具读取次数、解压次数、误恢复/丢约束率。
- 首次差异位置、理论最长共同前缀、reported实际hit、未归因稳定前缀miss。
- 任务成功率与质量，失败运行不能从费用分母中悄悄删掉。

### 3.4 放行规则

静态前缀不变量、direct-range锚点、单控制器、原文可恢复、固定工具序列、usage不双计必须100%通过确定性fixture。线上hit率不能承诺100%或固定94.2%；结果须带样本数、配对差异和不确定性。若候选在matched workload下费用、质量或延迟明显退化，必须定位并修正，不能靠平均命中率提高宣称通过。

参考工程目标：Nexus纯编排引入的额外本地开销P95不超过50ms（不含磁盘扫描、网络、索引、模型与宿主本身）；工具schema在稳定epoch内字节与顺序100%稳定；由时钟/主题/轮询引起的prefix变化为0；压缩后的质量不可低于预设任务容忍界限。性能数字是待测目标，发布报告可以基于测量修订，必须保留修订理由。

- 阅读视图成功折叠、失败不折、选择文本/滚动不跳、未知block回退。

- 旧方法/技能/记忆/任务迁移后都可发现和调用，不只在设置中显示“运行中”。

## 5. 故障注入

### 5.1 恢复事务

在intent落盘前后、每个文件rename前后、验证前后、host fork前后、flush前后、receipt前后强制中止。重启时判定文件preimage/postimage/rescue，未知状态保持 `recovery-required`。fork结果不确定先核验已创建child，不能盲重试；补偿时遇到第三方新编辑必须停下，不覆盖。

### 5.2 压缩事务

在原文blob写入、prepared block、血缘校验、投影commit、索引更新与usage落盘之间中止。恢复后允许丢弃未提交候选或继续幂等完成，不得出现原消息已隐藏而原文不可读。T2/T3来源损坏、重复id、循环血缘、旧legacy锚点都要有fixture。

### 5.3 扩展生命周期

工具注册后UI失败、UI成功route失败、新代启动失败、旧代dispose失败、watch连续变化、构建未完成、用户撤销授权、Host更新或退出。验证旧代保活、资源owner准确和重启恢复，不残留多重fetch/shell包装。

### 5.4 网络与usage

流式正文结束但usage未到、usage到达但UI断线、供应商缺字段/不同字段、兼容网关重写、余额API限流、key轮换、重定向、DNS变化、外部工具按次收费。结果不能把未知填0，不重复相加同义缓存字段。

## 6. 数据迁移与并行比较

迁移遵循 `discover → plan → preview → backup → import → verify → activate → monitor`。

1. Discover只读包/配置身份与公开的路径，不读取/回显key。
2. Plan列出来源格式、目标对象、ID映射、冲突、预计数据量、权限与失败策略。
3. Preview展示内容抽样与统计。记忆同名不直接覆盖；重复判断保留来源。
4. Backup可核验hash且能在未激活新插件时独立读回；不能把同一目录另一个临时文件当唯一备份。
5. Import使用checkpoint游标；逐对象receipt，重启续传。
6. Verify数量/完整性/权限/引用/索引；外部Provider失败不删除LOCAL原件。
7. Activate对每类能力逐个接管，防止双注入/双压缩。原插件配置保留回滚资料。
8. Monitor观察一段明确时间并保留差异。删除旧文件是另一个具名动作。

并行比较时，只有一个引擎有写入与模型注入权；另一个shadow读取与计算，不同时发送真实写请求或两套压缩。影子结果计入独立成本桶，不能隐藏在生产费用之外。

导入/导出格式必须版本化、路径与大小有界、secret排除、压缩包解压防越界。未知schema保持原件并给可理解错误，不自动用默认对象覆盖。

## 8. 发布与升级

发布前须有可review的精确包构件、版本、文件清单、sha/integrity、发行说明、兼容矩阵、迁移/回滚、notices和测试报告。包不能包含research归档、用户数据、密钥、未审核的巨大模型、临时缓存或上游整仓.git。

包内默认关闭自动执行外部依赖lifecycle。原生模块/二进制按OS/arch/ABI选择，签名与hash可核验；无对应构件时核心功能仍能工作，相关功能明确依赖。UI渲染和host backend共享schema版本，不能错版静默写入。

升级前探测活跃会话与扩展generation，保存配置与迁移点。运行中会话默认保留原有tool/prompt/memory epoch；新代码接管必须有语义兼容证明，否则下次会话生效。不能后台自更新压缩内核导致同一长程会话锚点算法改变。

发布、npm push、GitHub Release、外部通知和安装到用户profile属于实施后的实际动作；本次用户只要求规格，因此本次不执行。开发阶段有明确发布授权时复用授权范围，不人为重复增加审批。
