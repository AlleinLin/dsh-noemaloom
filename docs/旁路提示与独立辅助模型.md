# 旁路提示与独立辅助模型

本功能面向 Nexus 0.4.0。R19 冻结源码的构建、类型检查、1932 项回归和安装包审计已通过，已安装到 Windows Desktop。真实模型与桌面检查的具体范围、版本及未覆盖项见 `本轮验收.md` 与 `evidence/verification-summary.json`，不据此声称完成历史全规格验收。

## 官方资料与实现范围

核实日期：2026-10-20。主要来源是 Claude Code 官方 [Interactive mode: You should know suggestions](https://code.claude.com/docs/en/interactive-mode.md) 与 [CHANGELOG 2.1.287 / 2.1.288](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md)，另查阅 [Mods overview](https://code.claude.com/docs/en/plugins/mods/overview.md)、[interface](https://code.claude.com/docs/en/plugins/mods/interface.md) 和 [API](https://code.claude.com/docs/en/plugins/mods/api.md)。

官方公开行为包括：输入框上方一次显示一条建议；长任务期间通过无工具的 side request 重读会话与工具结果；用户引用前主代理看不到建议；Learn more 本地展开；Knew this already / Understood 记录已知主题；Dismiss 关闭；Chat in main session 将引用放入草稿，仍由用户发送；近期提示与已知主题跨会话去重。未展开便 Dismiss 后短时提供 Turn off suggestions。官方默认关闭，还有 first-party、功能旗标和遥测等适用条件。

用户提供的 [claude-cn 文章](https://www.claude-cn.org/posts/Claude-code-you-should-know.html) 与主要官方交互相符；[lpnh 文章](https://lpnh.cn/news/2535071) 中本地编译 Sonnet、离线推理、特定 AST 实现等内容未获官方材料支持，不作为依据。

Nexus 复用公开交互思路，使用自己的宿主接线和持久化，不是官方 Mods 组件，也不声称复现内部算法。官方描述同模型 side request；这里按用户要求改为单独配置、按序降级的独立请求。独立指配置和生命周期隔离，不禁止用户主动选择和主会话同名的型号。未配置不借用当前会话模型，不发送请求。

## 三种机制

1. **You should know**：根会话原生 pre-step、长任务周期及 turn-end 触发独立遗漏检查，允许返回 null。模型按一句不超过100字生成提醒；初始卡片最多两行，详细论证在 Learn more 后本地展开，详情区域独立滚动。提示与解释只显示给用户。展开不调用模型；引用使用原生 `captureInsertion` / `insertText` 版本校验，只改草稿不发送。未回答的单条提示保持稳定。近期与已知主题在同工作区跨会话去重，不跨工作区共享。只有未展开便忽略，才短时显示 Turn off suggestions。
2. **规划前与 review 深层问题**：阶段识别成功后，再执行独立、无工具的审阅；每任务每阶段成功一次。默认实际 system 包含用户原句：`在我最近反复讨论的问题背后，有没有一个更深的问题，是我一直再绕着它走，却没有真正问出来的`。设置可查看、编辑、恢复继承或使用默认 system，1至8000字符。设置修改不重发已完成阶段，新任务采用新提示词。结果不伪装成用户消息，也不回注主模型。
3. **调研完成后四问**：只接受结构化 `ready-to-propose`、`researchComplete=true`、`proposalStarted=false`，引用须是当前材料真实 `sessionId#seq`。确认栏最多等待60秒；用户点击才通过原生输入动作 Queue 提交。只有该真实消息是唯一 next-turn head、next-step 为空且支持正式 claim 时，宿主才正式 claim 并合入当前 pre-step。不删除或 splice 原生 inbox。未选择不创建消息；略过、超时、其他排队输入、取消或停用均继续主任务。等待真实 admission 最多另加10秒，不捏造投递成功，不取消主任务。

四问原文：

> 我想把这项任务做透彻，而不是做大。在继续进行之前，请先回答：1. 这个领域的顶尖专业人士在处理这项任务时，会做哪些我还没有要求的关键工作？2. 他们会从哪些最原始的一手材料着手，而不是依赖已经替我整理、概括或解读过的内容？3. 他们具体会使用哪些方法和工具？4. 不靠你我自己的判断，有什么外部依据或独立检验，能验证结果是否正确？

阶段是模型推断，可能未知、误判或错过调研和方案紧邻的边界，不能证明主代理内部意图。没有用关键词匹配代替模型判断；结构验证只能限制格式及引用，不能证明语义。普通真实用户新发言定义新任务 epoch，连续追问也可能成为新任务；精确四问文本不改变 epoch。

宿主自动入口为写动作提供独立 requestId。同会话的新输入立即取消旧观察，并按顺序完成已经准入的 invalidate 写操作；后续 observe / wait-gate 等待该屏障，防止迟到的撤销清除新确认栏、让四问意外留到下一回合。

任务指纹对原生消息使用规范化 JSON。正式 dispatcher 会排序对象字段；仅字段顺序变化不能被认作新任务，否则首轮提示和深层问题会在消息持久化后被清空。该合同由正式 dispatcher、原生消息构造及 Session.append 的组合回归验证。

## 设置与预算

入口为全局设置“意图识别与旁路审阅”或会话“本会话辅助设置”。全局 → 工作区 → 会话实时继承，仅保存本层明确覆盖。模型可多选、拖动或上下箭头排序；真实目录来自宿主 LlmRuntime，不存在型号不能保存。已知不支持 reasoning 的模型可选且不发送参数，元数据未知不可选。省略强度时用官方元数据最高支持值；显式值须在目录内。目录存在不证明凭据有效。

旧 insights / autonomy 成对显式 provider/model 可迁移为路线；`routes: []` 是明确未配置，不能再迁移或回退当前会话。旧任务分析与自动计划也使用共同独立路线。配置变更立即撤销旧观察 epoch。

网络、429、无效结构等失败按所选路线逐项降级并展示原因。每路45秒，250毫秒指数退避、最多3秒；供应商 retry-after 展示给用户。用户取消不尝试下一路。一次旁路检查（含摘要、归并、识别和深层问题）总预算120秒。默认每会话每日96个实际请求准入，降级与每个摘要都计数；共享预算还约束旧任务分析与自动计划，companion 界面计数仅显示本机制请求。日界为 UTC。

单次保守输入预算默认256000（允许4000至1000000），输出预算默认32768（允许512至65536）。输出额度包含模型思考消耗；仍限制提示、摘要和深层问题的可见正文长度。实际输出额度取调用方、辅助设置及宿主公开路由额度中的较小值；宿主目前该字段来源是 `LlmResolvedModelInfo.defaultMaxTokens`，作为保守上界，不声称它是供应商全部型号的硬性最大值。旧任务分析与自动计划省略预算时也继承此设置；已明确保存的较小额度继续生效。

已安装官方 `dsh-llm-deepseek` 的 Messages 适配器将 `GenerateOptions.maxTokens` 直接传给 `max_tokens`，同时通过 `thinking` 与 `output_config.effort` 启用相应思考强度；`max_tokens` 终态正式映射为 `kind: 'max-tokens'`。因此耗尽额度属于 `MODEL_OUTPUT_LIMIT / NX_MODEL_OUTPUT_LIMIT`，不能误报宿主不支持合同，更不能把截断但恰好可解析的JSON当作完整审阅。无工具请求返回 tool-calls 属于无效输出；缺失或未知终态才报告 `HOST_CONTRACT_UNSUPPORTED`。脱敏失败诊断只保留终态、额度、token数、正文字符数及调用/trace标识，不记录正文或私有思考。

无路线、总开关停用或三个 companion 开关全关时不做 companion 推理。get、设置、Learn more、已知、忽略与引用不调用模型。前端倒计时本地每秒更新；checking/pending 或已配置运行会话约2秒读取缓存，空闲约30秒，停用/未配置约120秒；隐藏页面暂停读取，可见恢复与本会话保存设置刷新。

## 上下文与缓存

读取本会话全部可访问原生事件及同工作区 origin=subagent 的后代，最多128会话。包含正文、完整工具参数/结果、子代理事件、生命周期和附件引用；排除私有 reasoning/thinking、凭据、二进制正文和未持久化数据。不读取 fork、其他工作区或磁盘文件。复用项目凭据规则，处理对象/字符串中的 API key、access/refresh token、authorization、cookie、URL 凭据等；规则过滤不是任意文本秘密的形式化保证。

官方 `assistant/message` 同时持久化已组装 `message.content` 和原始 compact stream，旁路只保留前者，省略重复 stream；没有已组装消息的 `assistant/attempt` 仍保留可见前缀与工具片段。两者都排除 reasoning/thinking 的正文、delta、compact chunks 及供应商不透明 replayState，避免私有思考通过原始流重新进入上下文。

界面报告事件数、会话边界、throughSeq、字符数、不可访问项及原文/有损模式。无法读取会话、嵌套超过32层、总字符或分段数超限会明确标记不完整，不执行声称全量的深层审阅。

材料向前稳定分段，每会话独立边界。超出单次容量则覆盖全部叶分段摘要，再最多四层分组归并，不选择尾部假称全量。摘要有损，无法保证保留全部细节。缓存键包含工作区、源分段、摘要 system 与有序路线；新尾部只重算受影响节点。最终请求还校验完整 system、材料和覆盖说明的输入预算。输入按 UTF-8 字节加边框开销保守估算，非供应商精确 tokenizer；超限失败，不截尾。

集合：`companion-state` 保存会话状态；`companion-topics` 保存工作区主题；`companion-context-cache` 保存摘要；`auxiliary-call-budget` 保存共享准入。默认保留30天，读取时淘汰过期主题/缓存。主题 ledger 可重试 CAS 保证不同会话并发不丢记录。状态串行写并受取消 epoch 保护。sent/skipped/expired 保留任务指纹，重启后过期 pending 转 expired。辅助 attempt 不合并主任务 AttemptOwner，其失败不能 dispose 或取消主任务；原生用量记账链继续生效。
