# 慢 I/O、超时与内存验证：0.1.2

这次检查确实发现了 0.1.1 的缺陷，因此交付更新为 0.1.2。有限测试不能证明绝对零 bug 或零泄漏。
测试通过可控延迟、忽略取消的假后端、无法退出的假进程及真实 SDK/PowerShell 执行；
没有拖慢整台电脑，没有关闭或绕过安全软件，也没有复现公司的 WMI/minifilter 环境。

## 已修复的问题

| 场景 | 0.1.2 的处理 |
|---|---|
| 后端忽略取消、很晚才返回 | 调用停止等待；实际 I/O 继续占槽，返回后检查取消，不继续读写、不回填缓存、不发观察记录 |
| 大量调用反复超时 | I/O 和搜索各有 128 条等待上限；排队取消会移除任务和监听器，队列满时明确拒绝 |
| 写入前获取 cwd、权限或 intent 卡住 | 准备阶段可取消，迟到结果不会派发变更 |
| 已经原子提交后发生取消 | 通过 SDK deferContext 保留已确认提交摘要；取消不代表回滚 |
| 提交摘要在真实 Agent 流程触发异常 | 改用官方 createUserMessage 生成完整 id/source；补字段断言，原版桌面重跑 12 次工具调用通过 |
| 后端在发布后报错、结果无法确认 | 保留“待核实”目标；先 fresh 读取，不盲目重试 |
| PowerShell 启动、排队或权限解析很慢 | 同一个调用期限覆盖准备、排队和执行，出队后只使用剩余时间 |
| PowerShell 不响应 terminate/kill | 清理等待有上限，未确认资源保留计数；`cleanupPending:true`，阻止该 agent 启动后续命令 |
| 搜索进程迟迟没有 close 事件 | 250ms 清理宽限后隔离追踪，不继续解析；未确认资源过多时拒绝创建新进程 |
| 进程反复重启保留旧对象 | 每 agent 复用一个生命周期清理回调，确认退出后移除输出监听器和进程条目 |
| 文件在 stat 之后突然变大 | 使用宿主有界 readBytes，超过单文件缓存阈值时退回流式读取 |
| 返回很小的行片段却保留大正文 | 显式复制受限行窗，避免 V8 substring 长期保留原始大字符串 |
| 编辑结果和批量结果过大 | 批量只保留摘要；单次修改前后正文合计超过 64KiB 时省略完整 diff |

复杂 glob 可使 Node 的匹配函数长时间占用 CPU。匹配现已移入独立 Node 进程，
固定脚本从 stdin 接收 JSON，限制输入 32MiB、old heap 64MiB、young semi-space 4MiB，
共用搜索期限、并发和终止追踪。保留 ignore-aware 快照及原有匹配语义；
相同模式复用结果，不同模式可复用目录快照，首次过滤增加一次进程启动。

## 资源边界

默认文件缓存 64MiB、最多 4096 条，按 UTF-16 字符串、键和元数据估算；
单文件进入缓存最多 2MiB，最多 8 个文件监听器。
目录快照全局 16MiB、最多 8 条；重复查询结果全局 8MiB、最多 8 条。
各预算均按插件实例计算。TTL=0 禁用缓存复用；销毁实例会清空缓存、队列和监听器，
迟到结果不能重新填充。

PowerShell 每实例最多 16 个前台受管资源，常驻进程每 agent 串行，
每队列最多 128 条。尚未确认退出的资源继续占位。
搜索子进程在模块级别追踪，最多 16 个；已有 2 个终止未确认的子进程时不再创建。
这些限制是负载过高时的拒绝机制，不能让已经卡在内核中的操作立即完成。

缓存预算不是整个 Desktop 的 RSS 限制。V8/原生分配器、SDK、当前 I/O 缓冲、
官方 listDir 一次返回的完整目录、原子变更的完整前后正文和 PowerShell 用户变量另占内存。
反复在常驻 PowerShell 中向全局变量添加数据会主动保留用户数据；空闲退出或隔离模式可释放该进程状态。

## 本轮实测

Windows x64、Node 24.19.0；`npm run check` 构建及 **87 项测试全部通过**。
独立扩展压力脚本 **6 项全部通过**，耗时 34.43s；完整数据见 resilience-results.json。
原版 Electron 的官方 standard 预设重新完成 12 次真实工具调用，包含新的隔离 glob 路径、
write/edit/batch_edit 的提交上下文、PowerShell 常驻与字面参数；不是只测 Web 或 CLI。

| 实验 | 结果 |
|---|---|
| 每次 provider 调用延迟 180ms，截止 60ms | 原始 SDK 读取顺序在 75.594ms 取消；已热 Forge 读取 0.375ms，零新增 provider 调用 |
| 150ms 后端读取故意忽略取消 | 调用方 29.433ms 返回，实际槽位保留至完成；迟到结果不填缓存 |
| 单独子进程阻塞事件循环 120ms，截止 20ms | 截止回调在 121.437ms 才运行；恢复后正确取消，无迟到观察或缓存，实际 I/O 最终归零 |
| 24 轮创建、压力、销毁 | 9600 次独特文件读取、288 对快照/查询；每轮销毁后缓存和队列归零 |
| 文件缓存设为 128KiB | 峰值估算 129400B / 131072B，未超过预算 |
| 快照缓存设为 256KiB | 峰值估算 168078B / 262144B，未超过预算 |
| 查询缓存预算 8MiB | 峰值估算 214964B / 8388608B，未超过预算 |
| 真实 PowerShell | 80 次持续调用及 4 次取消恢复；最终常驻、隔离与清理待确认计数均为 0 |

最后 12 轮销毁并 GC 后，堆使用量拟合斜率为 **−3297.93B/轮**，极差 310008B。
压力前堆为 9320752B；销毁并冷却 2s 后为 9787368B，比基线增加 466616B；
等待历史完整 30s 超时窗口后为 9788296B，相对冷却样本只增加 928B。
本次未观察到持续堆增长，不能据此推导所有路径绝对没有泄漏。
RSS 在冷却时约 95MiB，之后约 60MiB；RSS 与 GC 后 JS 堆分别记录，不混为缓存泄漏。

热读取实验显式使用 TTL=30000、watch=false，先预热再注入延迟；
交付默认仍是 TTL=1000、watch=true。这些数字不是公司机器收益，也不代表冷读取或写入能避免磁盘。
病理 glob 的重复通配符及 brace 扩张在独立子进程触发 200ms 测试期限时被终止，
父线程心跳仍运行；同步阻塞超过期限后的迟到搜索结果也不会成功或进入缓存。

## 必须保留的限制

1. 操作系统调度或 JavaScript 事件循环停顿时，计时器也会延后。期限不能保证在任意机器上精确到点返回。
2. 对已派发的真实写入继续等待后端确认，避免把“结果未知”冒称失败或回滚；不响应取消的写入仍可能很慢。
3. 常驻 PowerShell 用官方 managed range 确认清理。官方隔离 shell facade 只暴露执行生命周期，
   因此 `cleanupScope:provider-execution` 不声称证明所有脱离管理的后代均已退出。
4. 本机压力测试不能代替公司机器和企业策略实测。缓存命中避免重复 I/O，首次读、fresh 读和真实写入仍经过系统路径。
5. GC 后堆、RSS 和缓存计数含义不同。单次堆增长或 RSS 不下降不能直接判定泄漏；有限的平稳曲线也不能证明所有路径都没有泄漏。
