# Forge 权限参数说明

本说明适用于 Forge 0.1.4 的桌面端原生工具调用（权限防错从 0.1.3 引入）。普通读写、编辑与命令执行，
直接省略 `sandbox_permissions` 和 `justification`；工具在每次调用时读取该会话
当时实际的权限模式和工作区范围。工具注册时的默认模式不能代替本次调用的权限。
缓存、常驻 PowerShell 和重复调用也不能扩大这个范围。

## 参数怎样处理

`sandbox_permissions` 是单次扩大权限的请求。它的有效目标只有
`workspace-write` 和 `danger-full-access`，字段只会在相应宿主能力支持沙箱时暴露。
`read-only` 是会话模式，不能作为这个提权字段的目标。

| 调用参数 | Forge 处理方式 |
| --- | --- |
| 两个权限字段均省略 | 使用本次会话的实际策略 |
| 有效目标等于当前模式 | 按当前策略执行；重复字段和理由不触发审批，空字符串或空白理由也可省略 |
| 有效目标低于当前模式 | 忽略这个过时的提权请求，仍按当前实际策略执行；它不会把本次调用降级 |
| 只有字符串 `justification`，没有权限目标 | 忽略理由，按当前实际策略执行；包含空字符串、空白和非空理由 |
| 有效目标高于当前模式 | 要求说明本次操作所需权限的非空理由，并经官方用户审批后才可执行 |
| 未知目标或参数类型错误 | 拒绝调用；例如未知权限名、数字权限目标或非字符串理由 |

示例：当前会话已经是 `danger-full-access` 时，下面的重复参数不会触发提权审批：

```json
{
  "file_path": "src/example.txt",
  "content": "example\n",
  "sandbox_permissions": "danger-full-access",
  "justification": ""
}
```

日常调用仍建议只传操作所需参数。若希望降低权限，应使用桌面端访问模式控件，
让宿主更改会话策略；在提权字段填较低目标并不承担降权功能。

## 真正扩大权限时

当前会话模式不足时，只有合法且严格更宽的目标才走官方审批：
理由必须是非空字符串，审批服务、会话和调用上下文必须有效，
并且审批结果确实授权了本次请求。取消、拒绝、缺少审批渠道或理由无效时，
操作不会执行。批准仅供这一调用使用，不能改变后续调用的会话权限。

审批等待属于异步过程。用户可能在等待时更改访问模式或工作区；
批准返回后，Forge 会重新检查会话策略和取消信号。
若模式或工作区已经改变，停止这次操作，要求先核实当前状态。

`batch_edit` 仍逐项处理。真正需要提权的每项编辑分别遵守其审批流程，
没有一次审批覆盖整批文件的授权。已提交文件不会因后项失败自动回滚。

权限错误不会触发插件自动重试，也不会让命令自动转为完全权限或后台执行。
应先检查原始错误和当前模式，再决定是否提交符合范围的新请求。

## 参考 Ops 的范围

参考本机调研的 [T-Auto/dsh-ops](https://github.com/T-Auto/dsh-ops) 0.4.0 源码：
其文件工具不暴露这组提权参数，shell 接受重复的相同目标作为无须审批的操作，
而较低目标会报错。Forge 参考了按调用读取策略以及避免重复审批的设计，
同时保留自身的文件工具提权能力，并将有效的相同或较低目标都作为无须扩大权限的请求处理。
不能据此声称 Ops 的所有工具都采用与 Forge 相同的权限字段或参数语义。

## 适用边界

本说明覆盖 Forge 的原生工具入口，例如 `write`、`edit`、`batch_edit`、
`pwsh` 和 `pwsh_run`，以及实际暴露的权限字段。
官方 SDK 的顶层 `run_code` 入口、其他插件和宿主自身的校验不由 Forge 控制，
可能在调用 Forge 之前按自己的规则报错。安装 Forge 不会修改这些入口的校验逻辑。
